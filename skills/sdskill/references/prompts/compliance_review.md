# 文案违禁词与内容风险审查

## 目标

在交付前检查口播、字幕、标题、封面文字、发布文案、评论区引导和交易承诺。审查的是完整语义和实际表达，不是机械替换几个词。

此审查用于降低风险，不等于法律意见，也不能保证平台审核通过。

## 审查范围

1. **绝对化与无法证明的优越性**：如“最好、第一、顶级、全网最低、独一无二、国家级”等。结合语境判断，不把每个词机械判为违规；凡用于宣传且缺乏合法有效依据的，删除或改为可证明的具体事实。
2. **结果保证**：如“保证有效、百分百学会、稳赚、必瘦、永久、一次根治、无效退款”等。检查是否把个别体验、有限条件或概率写成确定承诺。
3. **虚假权威与证明材料**：如“官方指定、专家推荐、央视认证、销量第一、专利产品”等。没有可核验证据不得使用；有证据也要核对主体、范围和有效期。
4. **数字与比较**：收入、价格、销量、效果、折扣、排名、用户数量及竞品比较必须真实、有依据，不能用模糊措辞绕过事实要求。
5. **专业功效**：医疗、健康、美容、金融、教育、法律等领域不得夸大功效、承诺收益、制造恐慌或给出超出用户资质与证据的结论。
6. **误导营销**：检查虚假限时限量、虚构库存、虚构原价、伪造反馈、诱导互动和不实中奖信息。
7. **低俗、攻击与歧视**：检查辱骂、羞辱、性别或群体攻击、隐私曝光、诽谤和煽动网暴。观点鲜明不等于可以攻击具体个人。
8. **引流与交易表达**：检查是否包含平台限制的不当导流、私下交易或规避审核表达；按目标平台当前规则判断。
9. **其他内容载体**：不能只改口播而保留字幕、封面、图片、画面标识或配音中的同一风险。

## 审查流程

### 第一步：运行词库初筛

读取 `data/compliance_lexicon.json`，对待交付文案进行字面初筛。当前 AI 工具可运行 Python 时，在项目根目录执行 `python scripts/check_copy.py "<待检查文案文件>"`；不能运行时直接按 JSON 词条逐项检查。

词库说明和维护规则见 `data/compliance_lexicon.md`。命中只表示需要复核，未命中不等于合规；不得省略后续语义审查。

### 第二步：逐句找风险语义

标出原句、出现位置和表达目的。不要只搜索词表；同音字、拆字、谐音、缩写和换说法仍按实际语义审查。

### 第三步：核对事实与条件

- 有用户证据：确认证据是否真的支持这句话，是否遗漏适用范围和限制。
- 没有证据：删除，或改成不含未经证明结论的具体描述。
- 无法确认：标为“待核实”，不得以“可能合规”为由直接交付成可发布版本。

### 第四步：按发布环境复核

- 用户明确平台时，核对目标平台当前官方规则和行业要求。
- 有联网能力时，只使用当前官方规则或可靠的一手资料；记录核查时间供内部使用。
- 没有联网能力或无法确认最新规则时，明确写“平台规则未实时核验”，不能声称已经通过平台合规检查。

### 第五步：改写而不是规避

- 把“最好”改成真实、具体的差异。
- 把“保证有效”改成真实能提供的行动、内容或服务。
- 把“人人都能赚”改成有边界的过程说明。
- 无法证实又无法改写的句子直接删除。
- 不提供谐音、拆字、符号间隔等绕过审核的建议。

### 第六步：复查全稿

修改后重新检查标题、口播、字幕、封面、画面和发布文案，防止风险在另一载体中残留。

## 审查结论

内部记录使用三种状态：

- **通过初审**：未发现已知风险，但仍不代表平台保证通过。
- **修改后通过初审**：列出修改位置，并已复查全稿。
- **待核实／不交付**：关键事实、资质或最新规则未确认。

用户交付物只呈现必要的修改和待确认事项，不展示内部溯源。

## 脚本中的简要结果

```text
文案与风险审查：通过初审 / 修改后通过初审 / 待核实
已修改：
仍需用户确认：
平台规则核验：已核验 / 未实时核验
```

不要把“未发现风险”写成“绝对合规”或“保证过审”。
