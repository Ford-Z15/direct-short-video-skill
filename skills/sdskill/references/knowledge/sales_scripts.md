# 方法库：产品销售脚本

## 使用范围

用于有真实产品或服务、需要介绍卖点并引导咨询或购买的短视频。销售脚本必须基于真实体验、可证明卖点和现实交易条件，不把个别案例中的功效、价格或承诺写成用户事实。

## SALE-001｜按人群、场景、产品和行动组织销售表达

- **方法**：先明确哪类人在什么场景遇到什么问题，再引出产品如何解决，说明有证据的亮点，最后给出真实、清楚的咨询或购买方式。
- **编导动作**：逐段检查人群是否具体、场景是否真实、产品是否与问题对应、卖点是否有依据、行动指引是否可执行。
- **边界**：不虚构痛点、体验、库存、折扣或效果来填满结构；没有促销时不强行增加“逼单”话术。

## SALE-002｜开头优先呈现最有依据的优势

- **方法**：结构顺序可随产品真实优势调整。功能、使用前后变化、设计、价格或其他特点中，哪一项最有观看价值且证据充分，就优先呈现哪一项。
- **编导动作**：先列出候选卖点及证据，再决定从场景问题还是产品亮点开始；普通产品可使用基础结构，不机械套用固定顺序。
- **边界**：价格优势必须核对时间、规格、适用条件和真实售价；功能优势必须能被演示或材料支持。

## SALE-003｜用具体信息替代冗长推销和专业名词

- **方法**：一句话能说清的信息不拆成多句；把成分、参数和工艺翻译成观众能理解的使用场景、动作、感受或差异，同时保留必要事实条件。
- **编导动作**：删除重复劝说、强行反问和空泛形容；每句话至少承担说明问题、证明卖点、解释使用或指引行动之一。
- **边界**：口语化不等于夸大效果；专业信息不能为了好懂而改成未经证明的功效承诺。

## SALE-004｜真实使用后再做分享式表达

- **方法**：出镜者应先了解并实际使用产品，再写符合本人说话方式的文案；通过练习、拍摄前调动状态和面对真实交流对象，减少僵硬念稿。
- **编导动作**：脚本区分产品资料、出镜者真实体验和编导建议；没有体验时写“待体验确认”，不能代编“我用了很好”。
- **边界**：分享式语气只降低生硬营销感，不用于隐瞒商业推广关系，也不把主观体验扩大为人人有效的结论。

## SALE-005｜用场景、操作和细节证明卖点

- **方法**：销售画面可采用真实使用场景、操作过程、细节特写和可重复测试，让观众看到产品如何工作，而不是一直坐着干说。
- **编导动作**：每个核心卖点尽量对应一个可拍画面；边走边说只作为自然呈现方式，不能代替产品证据。
- **边界**：测试条件要一致、安全且能真实复现，不伪造前后对比、极端测试或测评数据；不为了分镜数量牺牲理解。

## SALE-006｜从多处资料研究产品，但独立核实

- **方法**：可参考同类视频、商家详情页、真实用户评价和常见问答，整理候选卖点、使用疑问和场景，再通过产品资料与实际体验核实。
- **编导动作**：记录每项卖点的依据；把评论中的问题当作选题线索，把重复出现的使用疑问转成脚本要回答的内容。
- **边界**：同行话术和用户评论不能直接当作事实；不得抄袭他人文案、伪造反馈或把商家宣传材料当作独立证明。

## SALE-007｜质疑与反转必须来自真实问题

- **方法**：欲扬先抑只能用于真实存在的疑问、限制或测试过程，例如先提出观众确实关心的问题，再展示核实过程和结论。
- **编导动作**：写清质疑依据、验证方式和最终结论；若产品确有不足，应保留限制和适用人群，不强行反转成全盘推荐。
- **边界**：不编造“我要打假”“千万别买”等负面钩子，不借贬低竞品或虚假质疑吸引停留；无法验证的质疑不进入发布稿。

## SALE-008｜ToB 获客脚本六类母结构

- **方法**：ToB 获客或专业服务的口播脚本可按六种母结构组织，选定母结构后按结构生成口播，仍须符合本模块口播标准（SALE-003）与文案审查。原方法论主张"不写逐字稿、用段落引导现场讲"，此处只吸收结构；具体交付成品口播还是段落引导，按用户拍摄习惯决定。

| 母结构 | 建议时长 | 结构 |
|---|---|---|
| 现场问题拆解型 | 35-60s | 问题 → 后果 → 常规做法 → 我们的做法 → 结果 |
| 方案取舍型 | 40-70s | 客户限制条件 → 客户真实需求 → 方案取舍 → 落地难点 → 最终效果 |
| 服务证据型 | 30-60s | 客户没空/不懂 → 我们替他做 → 发现问题 → 解决问题 → 留下证据 |
| 客户见证型 | 45-90s | 客户原声 → 担忧 → 动作 → 落地 → 评价 |
| 反常识避坑型 | 30-50s | 反常识结论 → 真实翻车 → 漏算成本 → 正确标准 |
| 主理人人物型 | 45-90s | 事件 → 选择 → 反馈 → 价值观 |

- **编导动作**：从《IP 定位档案》的心智词和高价值问题出发选结构——卖标准用反常识避坑型，卖过程用服务证据型，卖结果用客户见证型或方案取舍型，卖人用主理人人物型；每个结构环节必须有真实素材支撑，缺素材的环节回到用户访谈补事实。
- **边界**：母结构是组织参考，不替代钩子设计（hooks.md）和合规审查；"反常识结论"必须能被真实案例证明，禁止编造翻车或数据。

## SALE-009｜ToB 获客栏目体系与内容比例

- **方法**：长期获客账号从六类内容（TOP-008）中选 3-5 个组成固定栏目，并给出内容比例。默认参考比例：A 专业工艺与风险预判约 40%、C 服务流程约 25%、B 案例落地亮点约 15%、D 客户证言约 10%、E 人物故事约 10%，F 趋势场景按需穿插。
- **编导动作**：按定位档案选择栏目——定位卖标准则 A 类加重，卖服务则 C 类加重；为每个栏目定义内容边界（什么拍、什么不拍）和建议发布频率；比例随账号阶段调整（新号冷启动期 B/D 类可上调建立初步信任）。
- **与 POS-004 的关系**：POS-004 的"主赛道 6-7/10"是赛道口径，本比例是内容类别口径，两者并存不冲突——默认比例中 A+C 约 65%，与主赛道参考比例基本一致。
- **边界**：比例是规划起点不是固定科学配比；每季度按真实数据复盘调整，不机械执行。

## 销售脚本交付检查表

- [ ] 人群、场景、问题和产品是否真实对应？
- [ ] 开头优势是否明确且有证据，而非固定套用结构？
- [ ] 是否删除重复推销、空泛形容和未经证明的功效？
- [ ] 出镜者体验是否真实，商业推广关系是否按要求披露？
- [ ] 核心卖点是否有真实场景、操作、细节或材料支持？
- [ ] 价格、库存、优惠、资质、售后和行动指引是否已核实？
- [ ] 是否通过完整文案与风险审查，且没有伪造质疑或对比？
- [ ] ToB 获客脚本是否选定母结构（SALE-008），且每个结构环节有真实素材支撑？
- [ ] 栏目规划是否明确内容边界、发布频率，并说明比例将随数据复盘调整？
