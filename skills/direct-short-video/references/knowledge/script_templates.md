## 使用原则

模板是组织真实素材的结构，不是填空后自动得到成品的公式。先根据账号目的、内容类型、素材和拍摄条件选择模板，再写文案；不得把参考案例中的事实、数字或观点移植到用户项目。

## 两层结构：通用钩子＋类型主体

先设计钩子，再选择类型结构。钩子负责建立人群、场景和观看理由；类型结构负责交付知识、事件、过程、观点或销售信息。不得用同一条「问题—回答」结构处理所有内容。

| 类型 | 主体必备元素 | 结构检查重点 |
|---|---|---|
| 推荐 | 推荐对象、适用人群／用途、真实了解依据 | 不止罗列名称；不伪装亲身推荐 |
| 解题 | 待解决的具体问题、方法、真实示例或演示 | 方法能执行，保留适用条件 |
| 盘点 | 统一范围或标准、逐项信息、简短说明 | 各项标准一致，不虚构完整性或排名 |
| 避坑 | 真实错误／风险、对应改正方法 | 每个「不要」都有「可以怎么做」 |
| 热点 | 已核实事件、所选缘由／影响／交锋／立场主线 | 事实与观点分开，按对应子模板展开 |
| 手艺过程 | 展示方向、关键动作、变化与结果 | 镜头推进过程，删除重复和看不懂的动作 |
| 观点 | 明确服务对象、一致立场、少量有效论据、收束 | 中途不换写作对象，不让论据互相打架 |
| 销售 | 人群、真实场景问题、产品／服务、可证明卖点、真实行动方式 | 优势顺序可调整，证据和交易条件不可缺 |

内容结构与表达形式分开决定：结构决定「先说什么、后说什么」；真人口述、配音、信息画面、写实过程等决定「怎么呈现」。完成结构卡后再读取分镜方法，不因为口播方便就把所有内容做成一镜到底。

## 结构卡

```text
钩子原文与主机制：
内容类型与具体模板：
正文兑现顺序：
| 段落 | 功能 | 使用的真实素材 | 表达形式 |
收束／行动／下集尾钩（按需）：
```

逐句检查：每句话至少承担钩子、问题、方法、证据、示例、推进、收束或行动中的一项；重复、空泛、只表态而没有信息的句子删除或合并。

## 知识类

### TEMP-001｜推荐型

- **适用**：有真实可推荐的对象、资源或方法，并能说明其与观众需求的关系。
- **结构**：引发兴趣的开篇 → 依次推荐内容。
- **编导动作**：从素材库或用户真实经验中选择推荐项；开篇点明人群、用途或信息差，推荐项可按需补一句用途。
- **边界**：推荐必须真实了解，不把未使用、未核实的对象写成亲身推荐。

### TEMP-002｜解题型

- **适用**：观众有一个明确问题，用户能提供可执行的方法或示例。
- **结构**：待解决的问题 → 解决方法 → 实操举例。
- **编导动作**：把问题写成具体困扰，方法按行动顺序表达，再用真实例子或现场示范证明怎么用。
- **边界**：不承诺“百试百灵”等无条件效果；保留适用条件和必要风险。

### TEMP-003｜盘点型

- **适用**：同一类别下有多个值得并列介绍的对象。
- **结构**：开篇点明盘点主题 → 信息逐项罗列 → 每项附具体说明。
- **编导动作**：统一选择标准，控制每项解释长度，避免只有名称没有有效信息。
- **边界**：不得用“最、十大、全部”等词暗示未经证明的完整性或排名。

### TEMP-004｜避坑型

- **适用**：用户具备相关经验，能同时说明常见错误和正确替代方案。
- **结构**：风险或问题开篇 → 错误示例 → 改正方法，逐项交替。
- **编导动作**：每指出一个“不要”，就给出可执行的“可以怎么做”；原因解释服务于行动，不展开成专业讲座。
- **边界**：不恐吓观众，不虚构后果；专业领域的风险判断需要可靠依据。

## 热点类

### TEMP-005｜伸张正义型

- **适用**：热点中确有处于弱势或受损的一方，且事实关系已经核实。
- **结构**：开篇点题为谁发声 → 视频或口述复述事件 → 为弱者发声或指出另一方的不当之处 → 重申观点。
- **编导动作**：围绕已确认的责任关系组织论据，明确本条支持谁、理由是什么。
- **边界**：不得在事实不清时判定受害者、加害者；评论只能作为线索，不能直接复制为事实或他人原创文案。避免网暴、曝光隐私和煽动对立。

### TEMP-006｜事件缘由型

- **适用**：观众关心事件为什么发生，现有资料能支持原因分析。
- **结构**：一句话总结 → 简述事件 → 按时间线或因果罗列原因 → 总结点评。
- **编导动作**：交叉核对多份可靠资料，区分事实、当事人说法和分析推测；只保留能支撑主线的关键原因。
- **边界**：参考经验提到阅读五至八篇文章是操作建议，不是事实可靠性的保证；不得把多方转述当成已证实结论。

### TEMP-007｜未来影响型

- **适用**：热点与目标观众的生活、成本、选择或行业有明确关联。
- **结构**：一句话描述事件 → 阐述现状 → 可省略的原因分析 → 对观众的好处或后果。
- **编导动作**：优先回答“这与目标观众有什么关系”，把影响落到具体人群和场景；原因分析不必要时可删去。
- **边界**：预测必须标为判断并说明依据，不把可能性写成确定结果，不用虚构价格或政策制造焦虑。

### TEMP-008｜历史交锋型

- **适用**：热点涉及双方长期竞争、合作或冲突，并有可核实的历史材料。
- **结构**：一句话描述事件 → 简述本次事件 → 按时间线回顾过往交锋 → 简单点评或提问。
- **编导动作**：挑选改变双方关系或结果的关键节点，避免把脚本写成冗长年表。
- **边界**：核对时间、人物和结果；不把“吃瓜”叙事置于事实之上，不臆测私人恩怨。

- **热点类共同选择路径**：先看是否存在明确受损方，再看是否有值得解释的缘由、与目标观众相关的影响，或双方可核实的历史交锋。标题虽称“两大经典模板”，正文实际讲解以上四种结构，以正文为准，不补写其他模板。

## 手艺与过程类

### TEMP-009｜关键镜头法

- **适用**：烹饪、制作、维修、服务过程等能够用行动展示的内容。
- **结构**：确定展示方向 → 按过程列出关键动作镜头 → 删除重复、冗长和看不懂的镜头 → 按关键镜头拍摄。
- **编导动作**：每个镜头记录一个会推进过程或展示变化的动作，保留必要的开始、关键变化和结果。
- **边界**：参考材料中的手艺方向包括猎奇、接地气的展示，以及强调舒适和代入感的治愈方向；不能为了猎奇设计危险、浪费或虚假操作。

## 观点类

### TEMP-010｜先确定服务对象和一致立场

- **适用**：通过真实观点建立人物表达与观众关系，而不是提供操作教程。
- **结构**：确定本条对话的人群 → 找到其关系或行业中的冲突 → 明确一方观点 → 给出支撑理由。
- **编导动作**：人群类可从家庭、工作、社会关系中寻找冲突；行业类可围绕行业、产品、从业者、消费者，从误解、批判、支持、建议中选择方向。全篇保持写作对象一致。
- **边界**：立场必须符合用户真实价值观，不为了流量替用户站队；参考材料中的“大多数人认可”不能替代法律、安全和事实判断，也不鼓励攻击少数群体。

### TEMP-011｜归纳论证与反证

- **适用**：已有明确观点，需要组织理由和例子。
- **结构 A：归纳论证**：争议事件或话题开篇 → 表明观点 → 一个或多个论据 → 总结观点。
- **结构 B：反证**：先讲反面例子 → 再讲正面例子 → 总结观点。
- **编导动作**：选择少量最贴合用户经验的论据展开，不必把所有论据类型都塞进一条视频。

### TEMP-012｜六类论据提示器

| 类型 | 编导提问 | 使用边界 |
|---|---|---|
| 权衡利弊 | 这样做得到什么？不这样做失去什么？ | 收益和代价要有依据，不夸大 |
| 无奈之举 | 对方是否已尽力，但受现实条件限制？ | 不替用户虚构困境 |
| 不同视角 | 当事人和相关旁观者分别怎样理解？ | 各视角都要支撑中心观点，不中途换写作对象 |
| 针对评价者回应 | 如何回应不合理的评头论足？ | 仅回应不合理评价，不采用辱骂 |
| 倒打一耙 | 对方是否把责任错误地推给目标人群？ | 可用于识别责任错位，不用于歪曲事实或逃避责任 |
| 维度升级 | 从历史、未来或更长期影响看，结论是否不同？ | 趋势和预测必须标注判断依据 |

- **编导动作**：先把六类作为发散提示，再选一到两个最有真实材料支撑的方向展开；其余删除。

### TEMP-013｜观点开篇直接表达核心态度

- **适用**：标题过于学术、书面或与观众距离较远时。
- **结构**：把抽象议题改成与观众有关的明确判断，可用否定或带立场的表达增强情绪，再立即给出支撑。
- **编导动作**：比较疑问、肯定、否定等表达，选择最符合用户真实态度且信息最明确的一种。
- **边界**：参考经验中的“否定句大于肯定句大于疑问句”是开篇经验，不是跨场景定律；不得为增强情绪写成虚假绝对判断。

## 脚本输出检查

- [ ] 模板是否服务于账号目的和本条内容，而非只因“容易爆”而选用？
- [ ] 开篇、主体和结尾是否完整，且全篇只围绕一个中心任务？
- [ ] 每个事实、例子和论据是否来自用户资料或已核实来源？
- [ ] 观点类是否保持同一写作对象和一致立场？
- [ ] 避坑内容是否同时提供可行的替代方案？
- [ ] 热点内容是否区分事实、他人说法和编导判断？
- [ ] 手艺类是否列出可执行的关键镜头，而非只写抽象气氛？
- [ ] 是否删除案例口播中的数字、经历、观点和对用户的错误套用？
