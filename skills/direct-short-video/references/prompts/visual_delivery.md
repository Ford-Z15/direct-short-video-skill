# 可视化与素描图交付规则

## 1. 默认交付

涉及下列阶段时，可视化成品是正式交付的一部分，不用等待用户再次要求“画图”或“做成 PPT”。先生成内容与版式，再验证实际渲染结果；对话中先展示成品，再给文件位置。

| 阶段 | 文字成品 | 默认可视化成品 | 制作方式 |
|---|---|---|---|
| 市场调研 | `01b_market_research.md` | `01b_market_research.html` | 调用 PPT／演示文稿 Skill |
| 三个定位方向 | 调研报告中的方向与选择理由 | `02a_positioning_sketches/` | 代码绘制素描卡 |
| 分镜脚本 | `03_script.md` | `03_timeline_script.html`；辅助材料 `03b_storyboard_sketches/` | 优先生成标准时间轴表格，再用代码逐镜绘制构图素描 |
| 最终拍摄计划 | `07_shooting_plan.md` | `07_shooting_plan.html` | 调用 PPT／演示文稿 Skill |

只修改局部内容时，同步更新受影响的图和演示，不重建无关页面。所有文件仍保存在当前任务独立目录，不覆盖历史任务。

## 2. 调研报告与最终拍摄计划

1. 先完成事实、样本、结论和待确认项，再制作演示；图示不得新增没有依据的市场数据、客户信息或拍摄条件。
2. 通过宿主可用的 Skill 调用机制加载 PPT／演示文稿 Skill；用户指定或项目已提供 `guizang-ppt-skill` 时，遵循其页面、组件、备注和验证规范。
3. 默认交付浏览器可直接打开的单文件 HTML 演示，不要求用户安装依赖或启动服务器。只有用户明确要求 PPTX 时，才按宿主支持的流程另行导出。
4. 调研演示至少覆盖：样本与限制、账号格局、内容形式、客户痛点、差异化空间、三个定位方向。推荐方向可突出显示，但不能替用户作出最终选择。
5. 拍摄计划演示至少覆盖：本条任务、人员与设备、拍摄顺序、逐镜或分组镜头、安全与隐私边界、收工检查。必须与已确认脚本一致，不用视觉包装掩盖不可拍条件。
6. 若当前宿主没有 PPT Skill，明确告知后用 HTML／CSS 生成同等内容的单文件演示，不得静默省略可视化交付，也不得声称调用了未加载的 Skill。

## 3. 定位方向素描卡

- 为三个候选方向各画一张卡，与报告中的优先级和名称一一对应；用户选择后再将选定方向进入账号规划。
- 每张卡同时呈现：核心人物或主体、典型场景、主要动作、内容主线和一句定位表述。用不同主体关系、场景或镜头重心体现方向差异，不能只换标题和配色。
- 素描用于帮助用户理解内容呈现方式，不是品牌设计定稿，也不是竞品截图。不得虚构账号主页、粉丝数、播放量、客户评价或案例成果。
- 默认输出 3 张独立 SVG；可同时提供一张三联预览图。保存实际使用的生成脚本，便于后续修改。

## 4. 时间轴分镜表

- 分镜的主交付物是 `03_timeline_script.html` 标准时间轴表格，不是素描卡总览。每个镜头一个独立分镜单元，完整包含：`镜号／时间轴`、`画面描述／构图参考`、`台词／口播`、`情绪／语气`、`景别／机位／运镜`、`字幕／剪辑`。
- 台词字段保留该镜完整口播，不写“同上”“口述要点”或内容摘要；同镜多句按原顺序分段，条件尾钩单独标明保留或删除条件。
- 有实录时按实录标注时间；无实录时明确写“初剪参考”，说明估算口径，或只写切换点。不得把估算时长冒充精确成片时长。
- 桌面端默认采用单镜左右构图：左侧为逐项排列的文字表，右侧为同镜素描图；左表优先保证完整台词和画面描述。移动端将素描移到文字表下方，字段标题与内容不得错位。打印版避免跨页截断镜头、文字遮挡和横向溢出。
- 表格为静态可读成品即可，不强制添加动画、视频或交互。右侧素描图只辅助理解画面，不能替代左侧文字表或完整台词。
- 同步提供 `03_timeline_script.md` 或等价格式，方便用户复制、修改和迁入其他工具。

## 5. 辅助分镜素描图

- `03_script.md` 中每个分镜都必须有对应素描图，编号一致；不得只画封面或用几张装饰图代替逐镜分镜。
- 默认使用 9:16 竖幅线框：画清人物、物体、景别、构图、关键动作和必要运镜箭头；在图外标注镜号、画面类型、对应口播或切换点。
- 真人口述、写实镜头、信息画面和写意镜头采用可区分的构图。信息画面只放观众需要读的少量文字，不把整段口播塞进画面。
- 资料、重演、情景演示和示意画面在图上明确标注；不画客户名称、地址、人脸、车牌、文件等未授权信息，不用素描暗示危险操作可以由非专业人员模仿。
- 默认输出逐镜 SVG 和一张按顺序排列的总览图；需要 PNG 时再用本地工具转换。保留实际生成脚本。

## 6. 代码绘制与兼容边界

- 定位方向与分镜只用代码绘制素描图，优先手写 SVG 或 Python／JavaScript 本地生成；不调用视频模型，也不依赖视频生成服务。
- 默认使用米白底、深灰线稿和单一强调色，保持清楚即可，不追求照片级写实。不得把素描示意图当作真实案例或工程效果证据。
- 使用本地通用中文字体，不依赖远程图片、在线字体或外部服务。无第三方图形库时仍能生成 SVG。
- 宿主无代码执行能力但有文件能力时，直接写出完整 SVG 文件；无文件能力时给出可保存的 SVG 源码，并明确未能代为生成文件。

## 7. 交付前验证

- 实际打开 HTML 演示，检查页数、翻页或滚动、文字溢出、遮挡和移动端可读性；按所调用 Skill 的要求运行验证。
- 核对分镜单元数量、每镜六类字段、镜号和完整台词一一对应；桌面端逐镜检查左文右图，手机端检查上文下图，打印版检查镜头防跨页截断，并检查中文字体、字段标签、列宽、素描图、文字溢出与遮挡。
- 实际查看素描图渲染结果，不只检查代码语法。定位卡必须为 3 个不同方向，分镜图数量与分镜表逐项一致。
- 检查中文字体、画面主体、运镜箭头、图注和隐私提示是否清楚；发现溢出、错号或误导画面时先修正再交付。
- 验证只证明成品可显示、可理解、可执行，不代表播放量、获客或转化效果已经验证。
